# Подключение Google — пошаговая инструкция

Подключение состоит из двух независимых частей. Их можно делать по очереди.

| Часть | Что даёт | Как подключается |
| --- | --- | --- |
| Интерактивный доступ | Claude может по вашей просьбе смотреть Gmail и Google Drive прямо в разговоре | Официальные подключения claude.ai, вход в браузере |
| Служебный доступ для памяти | Ежедневная память сама дописывает один документ в вашем Google Drive | Отдельный ключ приложения Google, разрешение только `drive.file` |

Это разные доступы. Служебная память не видит вашу почту, а Gmail-подключение не участвует в ежедневной записи памяти.

---

## Часть 1. Интерактивный доступ к Gmail и Google Drive

Это делается прямо в Claude Code, без сайта Google Cloud.

1. Введите в строке ввода команду:

   ```text
   /mcp
   ```

2. В открывшемся списке выберите **claude.ai Google Drive** и подтвердите вход.
3. Откроется браузер. Войдите в свой аккаунт Google и разрешите доступ.
4. Снова введите `/mcp`, выберите **claude.ai Gmail** и так же подтвердите вход.
5. Вернитесь в Claude Code и напишите, что подключение выполнено.

После этого можно попросить, например: «покажи последние 20 писем» или «найди на Диске файл с таким-то названием».

Что уже зафиксировано в ваших настройках по почте:

- письма, точно совпавшие с вашими правилами очистки, перемещаются в корзину без отдельных вопросов;
- при сомнении письмо остаётся на месте;
- корзина автоматически не очищается;
- после пакетной уборки показывается один короткий отчёт.

## Часть 2. Служебный доступ для ежедневной памяти

Этой части нужен собственный ключ приложения Google. Он создаётся один раз.

### Шаг 1. Создать проект в Google Cloud

1. Откройте <https://console.cloud.google.com/>.
2. Войдите в тот же аккаунт Google, где будет храниться память.
3. Вверху нажмите выбор проекта и создайте новый, например `claude-daily-memory`.

### Шаг 2. Включить два API

Включите оба сервиса в этом проекте:

1. **Google Drive API** — <https://console.cloud.google.com/apis/library/drive.googleapis.com>
2. **Google Docs API** — <https://console.cloud.google.com/apis/library/docs.googleapis.com>

На каждой странице нажмите «Включить».

### Шаг 3. Настроить экран согласия

1. Откройте раздел «Экран согласия OAuth».
2. Тип: **External** (внешний).
3. Заполните название приложения и свою почту.
4. В разделе тестовых пользователей добавьте свой адрес Gmail.

Публиковать приложение не нужно. Режим тестирования подходит для личного использования.

### Шаг 4. Создать ключ приложения

1. Откройте раздел «Учётные данные».
2. Нажмите «Создать учётные данные» → «Идентификатор клиента OAuth».
3. Тип приложения: **Приложение для компьютера** (Desktop app).
4. Скачайте полученный файл JSON.

### Шаг 5. Положить ключ в защищённое место

Файл не должен попадать в проект или репозиторий. Правильное место:

```bash
mkdir -p ~/.config/claude-daily-memory
mv ~/Загрузки/client_secret_*.json ~/.config/claude-daily-memory/google-client.json
chmod 600 ~/.config/claude-daily-memory/google-client.json
```

### Шаг 6. Выполнить одноразовый вход

```bash
~/.local/share/claude-daily-memory/venv/bin/python -m claude_daily_memory.setup_google \
  --client ~/.config/claude-daily-memory/google-client.json \
  --config ~/.config/claude-daily-memory/config.json
```

Что произойдёт:

1. откроется браузер с входом в Google;
2. приложение запросит только разрешение `drive.file` — доступ к файлам, созданным им самим;
3. постоянный токен сохранится в системном хранилище паролей, а не в файле проекта;
4. в вашем Google Drive появится документ **Claude Daily Memory**;
5. в конфигурацию запишется только идентификатор этого документа.

Если Google покажет предупреждение о непроверенном приложении, выберите «Дополнительно» и продолжите: это ваше собственное приложение в тестовом режиме.

### Шаг 7. Проверить без отправки в интернет

```bash
~/.local/share/claude-daily-memory/venv/bin/claude-daily-memory build \
  --workspace "$HOME/tools/trailmark/workspace" \
  --projects-root "$HOME/projects" \
  --hmac-key "$HOME/.config/claude-daily-memory/hmac.key"
```

Откройте полученный файл и убедитесь, что содержимое вас устраивает.

### Шаг 8. Первая настоящая запись

```bash
~/.local/share/claude-daily-memory/venv/bin/python -m claude_daily_memory.job \
  --workspace "$HOME/tools/trailmark/workspace" \
  --projects-root "$HOME/projects" \
  --hmac-key "$HOME/.config/claude-daily-memory/hmac.key" \
  --config ~/.config/claude-daily-memory/config.json
```

### Шаг 9. Включить ежедневный запуск

```bash
systemctl --user enable --now claude-daily-memory.timer
systemctl --user list-timers claude-daily-memory.timer
```

Таймер намеренно оставался выключенным до этого момента.

## Часть 3. Подключить документ к NotebookLM

1. Откройте <https://notebooklm.google.com/>.
2. Создайте блокнот или откройте существующий.
3. Добавьте источник → **Google Диск** → выберите документ **Claude Daily Memory**.
4. Дальше этот источник пополняется сам, а вы работаете с накопленной памятью внутри NotebookLM.

Ограничение: в обычном аккаунте NotebookLM может потребоваться нажать обновление источника вручную. Проект намеренно не обходит это ограничение и не использует неофициальные способы входа.

---

## Что важно знать о безопасности

- Ежедневная память не читает стенограммы разговоров Claude Code.
- В документ не попадают полные запросы и ответы, команды, содержимое инструментов, письма и произвольные файлы проектов.
- Каждый материал и итоговый текст проверяются на ключи, токены, пароли и лишние личные данные до любой отправки.
- При любой ошибке или сомнении отправка отменяется целиком.
- Разрешение `drive.file` не даёт доступа к остальным файлам вашего Диска.
- Постоянный токен хранится в системном хранилище паролей.

---

## Если что-то пошло не так

| Проблема | Что делать |
| --- | --- |
| Google не вернул постоянный токен | Отозвать доступ в настройках аккаунта Google и повторить шаг 6 |
| Ошибка про хранилище паролей | Убедиться, что запущен системный менеджер паролей, и повторить |
| Ошибка доступа к API | Проверить, что включены оба API из шага 2 |
| Документ не обновляется в NotebookLM | Обновить источник вручную в интерфейсе NotebookLM |

Откат безопасен: отключите таймер командой `systemctl --user disable --now claude-daily-memory.timer`, отзовите доступ в аккаунте Google. Локальные файлы памяти при этом не удаляются.
