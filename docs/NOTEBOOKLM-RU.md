# Постоянная память NotebookLM и полный локальный MCP

[English](NOTEBOOKLM.md)

NotebookLM — основная часть Claude Daily Memory. Один постоянный блокнот получает очищенную дневную память, а тот же локальный MCP позволяет Claude работать со всеми остальными блокнотами и материалами аккаунта.

## Поддерживаемая схема

- Одно виртуальное окружение приложения: `~/.local/share/claude-daily-memory/venv`.
- Закреплённая зависимость: `notebooklm-py[browser,mcp]==0.8.0`.
- Локальная браузерная авторизация: `~/.notebooklm/profiles/<профиль>/`.
- Только локальный транспорт MCP `stdio`.
- Без HTTP listener, удалённого MCP, master token, `NOTEBOOKLM_AUTH_JSON` и переноса cookies в облако.

## Первоначальная настройка

Используйте единую setup-команду из главного README. Она выполняет локальный интерактивный вход, проверяет авторизацию настоящим пассивным тестом, создаёт или повторно использует точный блокнот памяти, без дублей подключает документ Google, регистрирует MCP из того же окружения и обновляет источник.

Стандартное название блокнота и источника — `Claude Daily Memory`. Точное название существующего блокнота можно передать через `--notebook-title`. Если найдено несколько точных совпадений, настройка останавливается и ничего не выбирает наугад.

## Полные возможности аккаунта

MCP не ограничен блокнотом памяти. В пределах возможностей upstream и аккаунта Claude может использовать блокноты, источники, чат по материалам, заметки, исследования, материалы Studio, скачивание и общий доступ. Удаление и расширение общего доступа требуют предварительного просмотра и отдельного явного подтверждения.

## Восстановление авторизации

Если MCP сообщает об истёкшей или недействительной сессии:

1. повторите единую настройку с тем же `--profile` и `--confirm`;
2. завершите локальный вход в браузере;
3. проверьте `claude mcp get notebooklm`.

Существующие документ Google, блокнот и источник используются повторно. Timer нельзя считать исправным, пока не прошли пассивная проверка входа и обновление источника.

### Запасной импорт cookies из Chrome

Используйте импорт Chrome cookies только тогда, когда обычный локальный вход не завершается. Такой импорт может открыть локальному инструменту более широкий набор браузерных cookies, чем изолированный вход. Если upstream CLI попросит, сначала закройте Chrome; внимательно проверьте выбранный профиль. Никогда не переносите полученное состояние на сервер, в задачу GitHub, чат или репозиторий.

## Выход и отзыв доступа

Перед удалением сессии отключите timer:

```bash
systemctl --user disable --now claude-daily-memory.timer
```

Используйте локальную команду выхода/профиля закреплённого CLI либо удаляйте выбранный локальный профиль только после проверки точного пути. Отзыв сессии в аккаунте Google также может отключить NotebookLM. Последующая настройка выполнит новый вход без дублирования блокнота памяти и источника.

## Честное описание реализации

`notebooklm-py` — сторонний MIT-клиент, использующий внутренние веб-RPC NotebookLM. Google не публикует их как стабильный пользовательский API, поэтому они могут измениться без предупреждения. Зависимость закреплена и проверяется синтетическими тестами контрактов команд, но после будущего изменения Google всё равно может понадобиться обновление проекта. См. [../THIRD_PARTY.md](../THIRD_PARTY.md) и [../SECURITY.md](../SECURITY.md).
