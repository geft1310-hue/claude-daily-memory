One installation

One venv contains the application, Google Drive/Docs, Gemini, browser support, pinned NotebookLM client, and local MCP. The timer stays off until unified setup completes Google OAuth, NotebookLM login and binding, Gemini keyring storage, source refresh, and MCP registration.

Privacy boundaries

No transcript harvesting

The automatic pipeline does not read raw Claude transcripts, full prompts/responses, commands, tool data, Gmail, or arbitrary project files.

Fail closed

Every selected input and the final digest are scanned before networking. Uncertainty stops the upload.

Local credentials

Google and Gemini secrets use the OS keyring. NotebookLM browser state remains local and is excluded from Git.

Local stdio only

No remote NotebookLM MCP, HTTP listener, cloud cookie transfer, master token, or credential environment export.

Transparent implementation

Consumer NotebookLM access uses pinned MIT dependency notebooklm-py[browser,mcp]==0.8.0 and internal Google web RPCs. Google changes can require an update or renewed local login. Deletion and sharing expansion require preview and separate explicit confirmation.
