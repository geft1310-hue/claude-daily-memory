# Claude Daily Memory

[English](README.md) · [Сайт](https://geft1310-hue.github.io/claude-daily-memory/ru/) · [Безопасность](SECURITY.md)

Claude Daily Memory делает **NotebookLM постоянной памятью Claude Code**. Программа собирает отобранные полезные результаты из проектов, удаляет опасные данные, один раз добавляет дневную запись в растущий документ Google и автоматически обновляет этот документ в одном постоянном блокноте NotebookLM.

Та же установка регистрирует полный локальный NotebookLM MCP в Claude Code. Поэтому Claude может работать **со всеми блокнотами вашего аккаунта NotebookLM**, а не только с постоянной памятью: с источниками, чатом, заметками, исследованиями, материалами Studio, скачиванием и настройками общего доступа.

## Один продукт и одна настройка

```text
Работа Claude Code во всех проектах
              ↓
отобранная и очищенная дневная память
              ↓
один растущий документ Google
              ↓
один постоянный блокнот памяти NotebookLM
(источник подключается и обновляется автоматически)
              ↓
через тот же локальный MCP Claude использует
все остальные блокноты и материалы NotebookLM
```

Второго установщика NotebookLM и отдельного режима продукта нет. `./install.sh` создаёт одно виртуальное окружение `~/.local/share/claude-daily-memory/venv`. В нём находятся Claude Daily Memory, Google Drive/Docs, Gemini, закреплённый клиент NotebookLM, браузерная поддержка и MCP-сервер.

## Что входит в v0.2.0

- Одна дневная память по нескольким проектам Claude Code.
- Локальный архив Markdown до любой облачной отправки.
- Проверка каждого материала и итогового текста на секреты и лишние личные данные с безопасным отказом при сомнении.
- Идемпотентная запись в один документ через официальные API Google Drive и Docs.
- Автоматическое обновление этого источника в одном постоянном блокноте NotebookLM.
- Полный локальный NotebookLM MCP для всех блокнотов, источников, чата, заметок, исследований, материалов Studio, скачивания и общего доступа.
- Gemini Developer API с ключом в системном хранилище паролей.
- Одна локальная установка, одна команда настройки и один пользовательский timer systemd.
- Без сбора стенограмм Claude, удалённого NotebookLM-сервера, master token и открытых файлов с облачными ключами.

## Быстрый старт

### 1. Установить

Нужны Linux, Python 3.11+, Claude Code, Git, пользовательские службы systemd и системное хранилище паролей Secret Service/keyring.

```bash
git clone https://github.com/geft1310-hue/claude-daily-memory.git
cd claude-daily-memory
./install.sh
```

Установщик намеренно не включает ежедневный timer.

### 2. Один раз подготовить Google OAuth

Создайте OAuth-клиент Google типа **Desktop app** и включите Google Drive API и Google Docs API. Сохраните скачанный JSON как `~/.config/claude-daily-memory/google-client.json`. Файл должен быть закрытым (`chmod 600`). Пошаговая инструкция: [docs/GOOGLE-RU.md](docs/GOOGLE-RU.md).

Также нужен ключ Gemini Developer API. Не вставляйте его в команду или конфигурационный файл: единая настройка запросит ключ скрытым вводом и сохранит в системном хранилище паролей.

### 3. Посмотреть план и запустить единую настройку

Сначала посмотрите, что будет сделано:

```bash
~/.local/share/claude-daily-memory/venv/bin/claude-daily-memory-setup \
  --client ~/.config/claude-daily-memory/google-client.json \
  --config ~/.config/claude-daily-memory/config.json
```

Без `--confirm` ничего не меняется. После проверки выполните:

```bash
~/.local/share/claude-daily-memory/venv/bin/claude-daily-memory-setup \
  --client ~/.config/claude-daily-memory/google-client.json \
  --config ~/.config/claude-daily-memory/config.json \
  --confirm
```

Одна команда выполняет всю настройку:

1. запрашивает узкое разрешение Google `drive.file`;
2. создаёт или повторно использует документ `Claude Daily Memory`;
3. открывает локальный интерактивный вход в NotebookLM;
4. проверяет сессию настоящим пассивным запросом авторизации;
5. без дублей создаёт или повторно использует постоянный блокнот `Claude Daily Memory` и его источник Google Диска;
6. сохраняет только нужные идентификаторы в приватной конфигурации с правами `0600`;
7. регистрирует `notebooklm-mcp` в Claude Code из того же окружения, через локальный `stdio` и выбранный профиль;
8. при отсутствии ключа Gemini запрашивает его скрытым вводом и сохраняет в keyring;
9. обновляет источник и включает timer только после успеха всех предыдущих шагов.

Чтобы использовать существующий блокнот с другим названием, укажите точное имя через `--notebook-title "Точное название"`. Профиль выбирается через `--profile ИМЯ`.

### 4. Проверить

```bash
systemctl --user status claude-daily-memory.timer
claude mcp get notebooklm
```

Собрать память локально без обращения к Google Drive и NotebookLM:

```bash
~/.local/share/claude-daily-memory/venv/bin/claude-daily-memory build \
  --workspace "$HOME/tools/trailmark/workspace" \
  --projects-root "$HOME/projects" \
  --hmac-key "$HOME/.config/claude-daily-memory/hmac.key"
```

Просмотрите созданный Markdown до того, как полагаться на ежедневный запуск.

## Что Claude умеет делать в NotebookLM

Зарегистрированный MCP предоставляет возможности закреплённой библиотеки `notebooklm-py`, а не урезанную обёртку вокруг одного документа. С учётом функций вашего аккаунта Google Claude может:

- видеть, изучать, создавать, переименовывать и описывать блокноты;
- видеть, читать, добавлять, обновлять и удалять источники;
- задавать вопросы по источникам и настраивать чат;
- создавать и использовать заметки;
- запускать и просматривать исследования;
- создавать, отслеживать, переименовывать и скачивать материалы Studio;
- просматривать и изменять общий доступ.

Удаление и расширение общего доступа — важные действия. Сначала должен быть показан точный план, затем требуется отдельное явное подтверждение. Первоначальная настройка такие действия не выполняет.

## Ежедневная работа и восстановление после сбоя

Ежедневная задача очищает входы и итоговую сводку, записывает локальный Markdown, один раз добавляет день в Google Docs, обновляет источник NotebookLM и продвигает `last_successful_day` только после успеха всей цепочки.

Если не сработал Drive, NotebookLM не вызывается. Если запись Drive прошла, а обновление NotebookLM — нет, день остаётся незавершённым. Следующий запуск безопасно повторит попытку: маркер Google не даст продублировать дневную запись, а источник NotebookLM обновится ещё раз.

## Границы приватности и безопасности

Автоматический сбор **не читает** JSONL-стенограммы Claude Code, полные запросы и ответы, сырые команды, данные инструментов, Gmail, произвольные файлы проектов и ответы NotebookLM. В журнале аудита остаются только коды событий, счётчики и HMAC-псевдонимы — без идентификаторов блокнотов/источников и содержимого документов.

Refresh token Google и ключ Gemini хранятся в системном keyring. Браузерная сессия NotebookLM остаётся локально в `~/.notebooklm/`; её нельзя публиковать или переносить в удалённый сервис. Поддерживается только локальный MCP `stdio`: проект не настраивает HTTP listener, удалённый MCP, перенос cookies в облако или master-token flow.

Доступ к пользовательскому NotebookLM реализован закреплённой сторонней MIT-библиотекой `notebooklm-py[browser,mcp]==0.8.0`. Она использует внутренние веб-RPC Google NotebookLM, поэтому после изменений Google может понадобиться обновление зависимости или новый локальный вход. Это честное описание реализации, а не отдельный режим продукта. Подробнее: [SECURITY.md](SECURITY.md) и [THIRD_PARTY.md](THIRD_PARTY.md).

## Восстановление входа NotebookLM

Если авторизация истекла, повторите единую настройку с `--confirm`: существующие документ Google, блокнот и источник будут использованы повторно. Обычный путь — локальный интерактивный `notebooklm login`. Импорт cookies из Chrome допустим только как запасное восстановление, если обычный вход не работает; он может открыть библиотеке более широкий набор браузерных cookies и должен выполняться только локально. См. [docs/NOTEBOOKLM-RU.md](docs/NOTEBOOKLM-RU.md).

## Разработка

```bash
python -m unittest discover -s tests
python -m build
```

Тесты синтетические и не требуют настоящих ключей Google или NotebookLM. Изменения должны сохранять порядок «сначала тест», безопасный отказ, двуязычную публичную документацию и запрет на публикацию credentials. См. [CONTRIBUTING.md](CONTRIBUTING.md).
