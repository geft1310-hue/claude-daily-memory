# Claude Daily Memory

**Русский** · [English](README.md)

## Превратите NotebookLM в долговременную память для Claude Code

Claude Code делает много полезной работы в десятках сессий, терминалов и проектов, но нужный контекст рассыпается. Вчерашнее решение осталось в одном терминале. Рабочий план — в другом проекте. Причина технического выбора исчезает вместе с завершённой сессией.

**Claude Daily Memory превращает эту разрозненную работу в растущую базу знаний NotebookLM.** Система собирает полезные результаты работы по всем проектам, готовит чистую дневную память и поддерживает документ Google Docs, который подключается к NotebookLM как обычный источник Диска.

Вместо того чтобы каждый раз начинать с нуля, вы получаете второй мозг, который растёт вместе с вашей работой.

> **Claude Code выполняет работу. Claude Daily Memory сохраняет полезные результаты. NotebookLM помогает понимать и повторно использовать их.**

> Ранняя версия. Начните с локального пробного запуска и просмотрите результат до включения выгрузки в Google.

## Какую боль это решает

Работа с ИИ порождает новый вид потери информации:

- важные решения разбросаны по множеству сессий Claude Code;
- несколько терминалов одновременно работают над разными проектами;
- планы, находки, компромиссы и незавершённые задачи потом трудно восстановить;
- сырые стенограммы разговоров шумные и могут содержать секреты и личные данные;
- вручную писать итог после каждой сессии легко забыть;
- NotebookLM полезен только тогда, когда его источники регулярно пополняются.

Итог знаком каждому: повторные объяснения, дублирующее исследование, забытые решения и ассистент, который знает о вашей работе меньше, чем мог бы.

## Что получается в результате

Возникает непрерывный цикл знаний:

```text
Работа в Claude Code в разных терминалах и проектах
                    ↓
Собираются полезные планы, решения, заметки, отчёты и активность
                    ↓
Формируется одна структурированная дневная память
                    ↓
Секреты и лишние личные данные блокируются до отправки
                    ↓
Документ Google становится растущим источником для NotebookLM
                    ↓
NotebookLM становится вашей общей памятью по проектам
```

Когда документ памяти подключён к NotebookLM, вы применяете к накопленным знаниям его собственные возможности, например:

- спросить, что было решено по функции и почему;
- сравнить подходы, использованные в разных проектах;
- восстановить незавершённую работу и открытые вопросы;
- подготовить сводку перед возвращением к старому проекту;
- найти повторяющиеся проблемы, допущения и зависимости;
- сделать конспекты, обзоры, FAQ, отчёты, карты знаний, аудиообзоры и другие материалы, доступные в вашем аккаунте NotebookLM;
- собрать цельную картину работы вместо поиска по разрозненным чатам.

Claude Daily Memory — это **слой пополнения и поддержки памяти**. NotebookLM остаётся местом, где вы ищете, анализируете, связываете и преобразуете эту память.

## Почему это удобно

### Одна память на всю работу с Claude Code

Несколько терминалов и проектов дают один дневной поток знаний. Больше не нужно вспоминать, в какой именно сессии был важный ответ.

### NotebookLM со временем становится полезнее

Источник растёт из настоящей работы: отобранные планы, решения, заметки, отчёты и общая активность. Чем регулярнее вы работаете, тем содержательнее становятся межпроектные вопросы.

### Никакого ежевечернего ритуала

Не нужно копировать разговоры и не нужно помнить про ручной итог. Ежедневная задача готовит память сама.

### Смысл вместо шума стенограмм

Сохраняются полезные результаты, а не каждое приветствие, неудачная команда, промежуточный вывод инструмента или повторное объяснение.

### Достаточно безопасно для настоящих проектов

Сырые стенограммы Claude никогда не читаются. Каждый выбранный материал и итоговая дневная память проверяются до любого сетевого запроса. Ключи, токены, cookie, приватные ключи, присваивания вида `.env`, подозрительные строки и лишние личные данные блокируются или скрываются.

### Сначала локально и с возможностью проверки

Сначала создаётся читаемый файл Markdown на вашем компьютере. Выгрузка в Google необязательна. Никакой телеметрии, скрытой аналитики и работы через браузерные cookie.

### Рассчитано на параллельную работу

Файловые блокировки, обезличенные идентификаторы проектов и сессий, детерминированный результат и идемпотентная запись в документ позволяют нескольким терминалам Claude Code работать одновременно без повреждения памяти и без дублей за один день.

## Что запоминается

Система намеренно избирательна.

**Включается:**

- отобранные планы;
- решения и их обоснование;
- полезные заметки;
- отчёты и результаты проверок;
- безопасные общие счётчики активности;
- группировка по проектам и датам.

**Никогда не используется как автоматический источник:**

- сырые стенограммы Claude Code;
- полные запросы и полные ответы ассистента;
- команды оболочки и данные инструментов;
- письма Gmail;
- произвольные файлы ваших проектов;
- пароли, cookie, токены и содержимое `.env`.

В этом суть продукта: **сохранять работу, а не чувствительный след вокруг неё.**

## Как подключается NotebookLM

Система создаёт и поддерживает документ Google Docs с названием `Claude Daily Memory`. Его нужно один раз добавить в NotebookLM как обычный источник Google Диска.

Дальше:

1. Сессии Claude Code дают полезные отобранные результаты.
2. Ежедневная задача объединяет результаты всех участвующих проектов.
3. Итог проверяется локально.
4. Документ получает одну дневную запись без дублей.
5. NotebookLM использует документ как источник после обычной синхронизации или обновления.

Неофициальный API NotebookLM не используется. Браузерные cookie Google не копируются. Робот входа Playwright не нужен. В обычном аккаунте NotebookLM может потребоваться ручное обновление источника; проект не обходит это ограничение.

## Быстрый старт

Требуется Linux, Python 3.11 или новее и `systemd --user` для расписания.

```bash
git clone https://github.com/geft1310-hue/claude-daily-memory.git
cd claude-daily-memory
./install.sh
```

Установщик создаёт отдельное окружение Python, локальные каталоги состояния, файл ключа и подготовленный ежедневный таймер. Таймер остаётся выключенным до завершения настройки Google.

Собрать локальную память, ничего не отправляя в Google:

```bash
~/.local/share/claude-daily-memory/venv/bin/claude-daily-memory build \
  --workspace "$HOME/tools/trailmark/workspace" \
  --projects-root "$HOME/projects" \
  --hmac-key "$HOME/.config/claude-daily-memory/hmac.key"
```

## Подключение Google и NotebookLM

Подробная пошаговая инструкция на русском: [docs/GOOGLE-RU.md](docs/GOOGLE-RU.md).

Кратко:

1. Создайте проект Google Cloud и включите Drive API и Docs API.
2. Создайте ключ OAuth типа «Приложение для компьютера».
3. Положите файл ключа в `~/.config/claude-daily-memory/google-client.json`.
4. Выполните одноразовую настройку из установленного окружения.
5. Войдите в браузере: фоновая запись запрашивает только `drive.file`.
6. Появится документ `Claude Daily Memory`.
7. Один раз добавьте его в NotebookLM как источник Диска.
8. Включите таймер после успешной локальной и облачной проверки.

Постоянный токен хранится в системном хранилище паролей, а не в репозитории, `.env`, аргументах процесса или обычном файле.

## Безопасное поведение при сбоях

Выгрузка устроена по принципу «при сомнении — отказ»:

- каждый выбранный материал проверяется до включения;
- вся дневная память проверяется ещё раз;
- испорченные данные, нечитаемое состояние, ошибка проверки, недоступное хранилище паролей, ошибка входа и подозрительное содержимое отменяют отправку;
- состояние Google продвигается только после подтверждённого обновления документа;
- в журнале аудита остаются счётчики и названия правил, а не найденный секрет.

Ни одна проверка не даёт стопроцентной гарантии. Просмотрите локальный результат перед первой выгрузкой и используйте отобранные материалы, а не произвольные выгрузки текста.

## Не только память

В репозитории есть намеренно отделённые дополнительные инструменты:

- **обратимая очистка Gmail по правилам** — точные совпадения перемещаются в корзину без вопросов по каждому письму; сомнительные совпадения не трогаются, корзина автоматически не очищается ([docs/GMAIL-RU.md](docs/GMAIL-RU.md));
- **мост к Gemini по явному тексту** — отправляется только текст, указанный в команде; мост не может сам добраться до Gmail, Диска, файлов проектов, памяти или буфера обмена.

Эти инструменты не входят в автоматический сбор памяти. Содержимое почты и ответы Gemini не попадают в память NotebookLM.

## Архитектура

```text
Хуки жизненного цикла Claude Code        Отобранные материалы Trailmark
(только время, событие, проект,           (план, решение, заметка, отчёт)
 разрешённое имя инструмента)
                 \                      /
                  \                    /
                   └─ локальный сборщик дня
                              ↓
                проверка каждого материала
                              ↓
                проверка итогового текста
                              ↓
             локальный Markdown и безопасный аудит
                              ↓
       официальные API Google Drive и Google Docs
                 разрешение OAuth drive.file
                              ↓
          документ Google → источник NotebookLM
```

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

Тесты покрывают:

- одновременную запись из нескольких терминалов;
- границы проектов и объединение идентификаторов проекта;
- отклонение полей стенограмм;
- распространённые форматы секретов и строки высокой энтропии;
- скрытие личных данных без порчи дат;
- детерминированный дневной результат;
- идемпотентность записи в документ Google;
- точные и сомнительные совпадения правил Gmail;
- требования к таймеру и песочнице systemd.
